# Coding Conventions

**Analysis Date:** 2026-09-16

## Language & Runtime Baseline

- **Language:** Python 3.14 (venv: `venv/pyvenv.cfg` reports `version = 3.14.4`). The Dockerfile (`Dockerfile`) targets `python:3.11-slim`, so new code must stay compatible with 3.11+ syntax.
- **Style baseline:** PEP 8 with modern typing. No formatter/linter config exists anywhere in the repo (no `pyproject.toml`, `setup.cfg`, `.flake8`, `ruff.toml`, or `mypy.ini`). The `.gitignore` template dropped `.ruff_cache/` (see `template.py`), so tooling was intentionally removed.
- **State of the code:** only the ingestion pipeline is implemented. Files with real code: `app/config.py`, `app/ingestion/models.py`, `app/ingestion/extractor.py`, `app/ingestion/extractors/firecrawl.py`, `tests/conftest.py`, `tests/test_firecrawl_extractor.py`. All other files under `app/`, `tests/`, and `scripts/` are 0-byte stubs generated by `template.py`. Follow the conventions below when filling them in.

## Naming Patterns

**Files:**
- Modules: lowercase snake_case describing responsibility — `extractor.py`, `models.py`, `config.py`, `firecrawl.py`.
- Tests: `test_<module_under_test>.py` (e.g., `tests/test_firecrawl_extractor.py` for `app/ingestion/extractors/firecrawl.py`).
- Package dirs mirror the architecture layer: `app/ingestion/extractors/`, `app/api/routes/`.

**Classes:**
- PascalCase nouns — `Settings`, `ExtractedDocument`, `FirecrawlExtractor`, `WebExtractor`, `ExtractionError`.
- Custom exceptions are a named hierarchy: `ExtractionError` base with `UnsafeURLError`, `FetchFailedError`, `EmptyExtractionError` subclasses (`app/ingestion/extractor.py:20-41`).

**Functions:**
- snake_case verbs; async functions named with the operation (`validate_fetch_url`), sync workers suffixed `_sync` (`_validate_fetch_url_sync` in `app/ingestion/extractor.py:57`).
- Factories: module-level `get_extractor()` (`app/ingestion/extractor.py:90`) and classmethod `from_settings()` (`app/ingestion/extractors/firecrawl.py:47`).
- Test helpers: prefixed `fake_` / `make_` (`fake_result`, `make_extractor` in `tests/test_firecrawl_extractor.py:37-52`).

**Variables:**
- snake_case. Private instance state is underscore-prefixed in the Firecrawl extractor (`self._api_key`, `self._client`, `self._min_content_length` — `app/ingestion/extractors/firecrawl.py:38-45`).
- Private module-level helpers underscore-prefixed: `_is_blocked_ip`, `_validate_fetch_url_sync` (`app/ingestion/extractor.py:44-57`).

**Types:**
- Builtin generics with `from __future__ import annotations`: `str | None`, `list[str]`, `dict`.
- `typing.Protocol` defines interfaces: `WebExtractor` (`app/ingestion/extractor.py:13-17`).
- Type hints on **every** function signature, including `__init__` return `-> None`. Underscore numeric literals for money/time-scale ints (`30_000`, `min_content_length: int = 200`).

## Code Style

**Formatting:**
- No formatter configured. Observed style: 4-space indent, double quotes, ~88-100 char lines, blank lines per PEP 8 (two between top-level defs, one inside classes).
- Keyword-only constructor parameters after `*` (e.g., `FirecrawlExtractor.__init__` signature at `app/ingestion/extractors/firecrawl.py:24-35`).

**Linting:**
- No linter configured. Type-check pragmas used in code where third-party stubs are incomplete: `# type: ignore[attr-defined]` (`app/ingestion/extractors/firecrawl.py:12`).
- `# pragma: no cover` marks defensive branches not worth testing (`app/ingestion/extractors/firecrawl.py:13`).

**Typing discipline — use:**
- `str | None` / `list[str]` unions with `from __future__ import annotations` (see `app/ingestion/models.py:1`, `app/ingestion/extractor.py:1`) — do not use `typing.Optional`/`typing.List`.
- Return-type annotations on all public functions. `None` return must be explicit: `def __init__(...) -> None:`.

## Import Organization

**Order:**
1. `from __future__ import annotations` first (when unions are used).
2. Standard library group (alphabetical): `import asyncio`, `import ipaddress`, `import socket`, `from functools import lru_cache`, `from typing import Protocol`, `from urllib.parse import urlparse`.
3. Third-party group (alphabetical): `import certifi`, `from pydantic import Field, field_validator`, `from pydantic_settings import BaseSettings, SettingsConfigDict`.
4. Local `app.*` group last: `from app.config import Settings, get_settings`.

Each group separated by a blank line. See `app/config.py:1-6` and `app/ingestion/extractor.py:1-10` for the canonical layout.

**Path Aliases:**
- None. Imports are absolute from the package root: `from app.ingestion.models import ExtractedDocument`. Never use relative imports in application code.

**Lazy imports:**
- Heavy/optional providers are imported inside functions to defer cost and avoid import cycles — `from app.ingestion.extractors.firecrawl import FirecrawlExtractor` inside `get_extractor()` (`app/ingestion/extractor.py:94`).
- Optional dependency imports are wrapped in `try/except ImportError` with a `# pragma: no cover` and a raised error naming the pip command (`app/ingestion/extractors/firecrawl.py:11-16`).

## Error Handling

**Patterns:**
- A small domain-exception hierarchy, one class per failure mode, distinguished by a `code` class attribute:
  ```python
  class ExtractionError(Exception):
      code: str = "extraction_failed"
      def __init__(self, url: str, reason: str | None = None) -> None: ...

  class UnsafeURLError(ExtractionError):
      code = "invalid_url"
  ```
  (`app/ingestion/extractor.py:20-41`)
- **Always wrap third-party failures into domain errors with `raise ... from exc`** to preserve the chain:
  ```python
  except Exception as exc:
      raise FetchFailedError(url=url, reason=str(exc)) from exc
  ```
  (`app/ingestion/extractors/firecrawl.py:85-86`)
- Errors are raised with context arguments (`url`, `reason`) and a message built in `__init__`; tests assert on `.code` and substring-message (`tests/test_firecrawl_extractor.py:103, 124, 135`).
- Public guard functions validate first and raise the specific error type (`UnsafeURLError` for SSRF rejections in `app/ingestion/extractor.py:57-81`).
- Message strings interpolate with `!r` for values: `f"unsupported scheme {scheme!r}"`, and attribute-lookup errors use `getattr(result, "markdown", None)` defensively for untrusted API payloads (`app/ingestion/extractors/firecrawl.py:90-94`).

## Logging

**Framework:** stdlib logging configured via settings (`log_level: str = "INFO"` in `app/config.py:21`). No logging calls exist yet in the implemented code.

**Patterns:**
- Keep secrets out of all output — there is an explicit regression test `test_api_key_never_leaked_in_errors` (`tests/test_firecrawl_extractor.py:146-153`). Never log or include `api_key` values in exception messages.

## Comments

**When to Comment:**
- Explain *why* non-obvious behavior exists, not what the code does:
  ```python
  # SSRF guard. Rejects non-HTTP schemes and hosts that resolve to
  # loopback, link-local, private, reserved, or unspecified addresses.
  ```
  (`app/ingestion/extractor.py:85-86`)
- Section-divider comments with dashes inside test files separate test groups:
  ```python
  # ---------------------------------------------------------------------------
  # SSRF guard
  # ---------------------------------------------------------------------------
  ```
  (`tests/test_firecrawl_extractor.py:171-173`)

**Docstrings:**
- Triple-quoted docstrings on classes and public functions (module, class, and function level). Protocol methods use `...` bodies with a docstring (`app/ingestion/extractor.py:13-17`).
- `@pydantic` fields carry `description=` for secret-hygiene documentation: `Field(default="", description="Secret; must come from environment/.env")` (`app/config.py:26`).
- No JSDoc/TSDoc-style markup; plain prose docstrings. No `TODO`/`FIXME` comments exist in the implemented code.

## Function Design

**Size:** Functions are small and single-purpose. The largest implemented function is `_validate_fetch_url_sync` at 25 lines (`app/ingestion/extractor.py:57-81`). Keep new functions under ~30 lines; split with `_`-prefixed private helpers otherwise.

**Parameters:**
- Keyword-only parameters for constructors with many options (`FirecrawlExtractor.__init__` accepts 8 keyword-only args with defaults).
- Dependency injection over global access: clients are passed in as constructor args (`client: AsyncV1FirecrawlApp | None = None`) so tests can substitute fakes.
- Settings are injected rather than imported: `get_extractor(settings: Settings | None = None)` falls back to `get_settings()`.

**Return Values:**
- Typed data objects (dataclasses) instead of raw dicts: `async def extract(self, url: str) -> ExtractedDocument` (`app/ingestion/extractors/firecrawl.py:73`).
- Named tuples / `SimpleNamespace` for throwaway test doubles (`tests/test_firecrawl_extractor.py:37-43`).
- Failure is signaled by raising domain exceptions, never by returning `None`/empty from successful paths.

**Async:**
- Async boundaries are explicit: SSRF DNS resolution runs in a thread via `asyncio.to_thread` (`app/ingestion/extractor.py:87`), preserving the event loop. Follow this pattern for any new blocking I/O.

## Module Design

**Exports:**
- Public API surface is implicit (no `__all__`): classes and functions are importable by name. `__init__.py` files are package markers only.
- Provider implementations live under `extractors/` subpackage and are surfaced through the `get_extractor()` factory — callers depend on the `WebExtractor` Protocol, not the concrete class.

**Barrel Files:**
- Not used. Import the concrete module path (`from app.ingestion.extractors.firecrawl import FirecrawlExtractor`).

**Models:**
- Data structures are `@dataclass` with `field(default_factory=...)` for mutable defaults — never mutable literals:
  ```python
  @dataclass
  class ExtractedDocument:
      content: str
      source: str
      title: str | None = None
      metadata: dict = field(default_factory=dict)
  ```
  (`app/ingestion/models.py:4-9`)

**Configuration:**
- All runtime config lives in `Settings` (pydantic-settings, reads `.env`), fetched through a cached singleton:
  ```python
  @lru_cache(maxsize=1)
  def get_settings() -> Settings:
      return Settings()
  ```
  (`app/config.py:46-47`). New config keys are added as typed `Settings` fields, not ad-hoc `os.environ` reads. `os.environ.setdefault("SSL_CERT_FILE", certifi.where())` at module import (`app/config.py:8`) is the one sanctioned module-level side effect.
